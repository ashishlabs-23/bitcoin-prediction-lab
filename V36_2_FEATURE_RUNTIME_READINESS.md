# BTCognitive V36.2 — Feature Runtime Readiness

## Scope and status rules

This reconciles all **32 ENG records** in `V36_1_FEATURE_REGISTRY.csv` with their source entry points and call/test evidence. An ENG record is a capability group, not necessarily one atomic feature; bundled distinct calculations are named below. Call sites do not prove runtime reachability, and tests are listed as scope only: tests were not run in this milestone. `ACTIVE_UNVALIDATED` describes code lifecycle, not a validated predictor. No feature is `ACTIVE_VALIDATED`.

Registry lifecycle counts: **17 `ACTIVE_UNVALIDATED`, 8 `EXPERIMENTAL`, 4 `DATA_UNAVAILABLE`, 2 `DISABLED`, 1 `BROKEN`, 0 `ACTIVE_VALIDATED`, 0 `DEPRECATED`**. These are counts of ENG groups, not counts of individual input fields or algorithms.

### Additional distinct fields/candidates grouped under ENG records

The ENG registry also groups log-return lags, moving-average slopes, EMA ratios, trend filters, Donchian channels, ATR, ADX, VWAP, RSI, volume/range measures, volatility stress/regime certainty, TSMOM, range/Bollinger, higher-timeframe range-expansion, and microstructure measures (imbalance, spread, OFI, CVD, depth, impact). Liquidation, on-chain, macro, and sentiment fields appear in workstream designs but have no admissible local source. Their redundancy report is qualitative, not a measured correlation/ablation. All unobserved inputs remain unavailable; no synthetic proxies are admissible.

## Dataset-to-feature readiness

| Data | Features conditionally computable | Not supported |
|---|---|---|
| Hash-matched but provenance/semantics-gated Bitstamp-declared 1m CSV | Resampled historical OHLCV fields, PIT features, 15m A1/A2 candidates, 1m barrier labels—only after explicit candle-boundary/source semantics are accepted and resolver defects are addressed. | Current-market claims, order-book data, funding/OI/liquidations, calibrated directional or three-class outcome probabilities. |
| Verified Coinbase V2/V3 hourly series | Hourly OHLCV-derived historical volatility/regime/state calculations with 13 gaps explicitly excluded/segmented. | Exact frozen HAR-RS-DOW reproduction; Bitstamp candidate-contract fills; current-market use. |
| Coinbase 15m file | Short-span 15m OHLCV features/candidate calculation after its timestamp convention is fixed. | Multi-year validation, Bitstamp venue-specific label equivalence, 1m intrabar path resolution. |
| Bitstamp 1h snapshots (1k–4k rows) | Short-window hourly descriptive features within warmup limits. | Multi-year validation; does not meet 1m/15m entry-path contract. |

Runtime execution, causal correctness, and predictive validation are separate gates. The local codebase exposes many calculators and diagnostics, but **no feature has demonstrated incremental predictive contribution here**. No feature was executed in V36.2.
