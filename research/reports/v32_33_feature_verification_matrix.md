## 1. Feature Inventory & Verification Methodology

Every functional component of BTCognitive has been audited against active repository code, executable tests, API contracts, and live browser runtime behavior. No feature is marked `VERIFIED` based merely on code existence, HTTP 200 status, or DOM presence without behavioral verification.

### Status Definitions:
- `VERIFIED`: Control performs advertised action, calls correct endpoint, returns documented schema, handles error/stale states, backed by automated tests and running application verification.
- `PARTIALLY_VERIFIED`: Core workflow operational, but secondary features or prospective observation accumulation ongoing.
- `FAILED`: Control, calculation, or integration broken or inconsistent.
- `BLOCKED`: Feature depends on unavailable live external dependencies (e.g., live broker execution deliberately fail-closed).
- `NOT_TESTED`: Untested component.
