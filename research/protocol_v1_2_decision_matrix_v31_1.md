# V31.1 Statistical Protocol Decision Matrix

**Status:** `PROPOSAL — HUMAN REVIEW REQUIRED`  
**Date:** 2026-10-23  
**Protocol relationship:** This is an addendum to the unapproved V1.2 proposal. It does not amend frozen V1.1, authorize a confirmatory gate, or define an approved sample-size threshold.

## Decision matrix

| Protocol question | Proposed treatment for review | Why / limitation | Human approval still required |
|---|---|---|---|
| Primary question | For a frozen strategy under a fixed venue/product/cost and allocation contract, estimate whether its common-window calendar-time net return improves on a frozen, timestamp-aligned benchmark. Keep per-setup net R, barrier hit rate, and excursion statistics secondary and descriptive. | Calendar-time returns incorporate inactivity, holding time, concurrent exposure policy, and turnover. Trade-level means alone can make a strategy with sparse, long-duration trades look comparable to a continuously exposed strategy. | Confirm the business/research question, benchmark, capital and exposure convention, and economically meaningful minimum effect. |
| Eligible evidence unit | One common, chronological decision-time interval in the untouched test period, with candidate and benchmark returns aligned on the same interval. Maintain a separate audit of initiated setups, fully resolved outcomes, pending outcomes, and exclusions. | A candidate/trade count is not the number of independent observations. Overlapping labels and serial dependence remain even when some positions are non-overlapping. | Freeze interval frequency, position overlap/capital allocation, and handling of incomplete or invalid observations. |
| Primary estimand | Mean paired net calendar-time return difference, candidate minus benchmark, over the frozen test window; state the return unit and aggregation before seeing test results. | This tests net research performance for the specified portfolio simulation; it does not prove live fills, profitability at a different venue, or directional accuracy. | Freeze the exact return definition, notional/compounding convention, and benchmark. |
| Secondary entry estimands | Report net R per resolved setup, TP/SL/timeout proportions, MFE/MAE, holding duration, and calibration only when their denominators and eligibility rules are explicit. | Trade-level outcomes answer entry/barrier questions, not the same question as calendar-time performance. Setup generation, expiry, and selection can change the denominator. | Approve each secondary metric and its denominator; no metric may replace the primary estimand after results are seen. |
| Benchmark alignment | Use the same frozen time intervals, source, instrument, bar-availability rule, and cost scenario. Include zero exposure/no-trade as a transparent reference; any active benchmark must have a frozen rule and identical evaluation windows. | Comparing trades from different timestamps or using candidate-specific windows breaks paired interpretation and permits selection effects. | Select the benchmark and any active comparator before test access. |
| Uncertainty | Report a two-sided 95% interval for the primary effect. Use a preselected dependence-aware method (e.g. HAC interval or stationary/block bootstrap on the aligned calendar-time difference series) and report sensitivity to plausible dependence settings. | The method must reflect serial dependence and the chosen estimand. A bootstrap expected block length is a dependence parameter, not a multiplier that turns observations into an effective sample size. | Approve the interval method, dependence diagnostics, block-length selection rule, and sensitivity set before evaluation. |
| DM-HLN | Reserve Diebold-Mariano with Harvey-Leybourne-Newbold finite-sample correction and Student's t reference distribution with `T-1` degrees of freedom for aligned forecast-loss differential sequences with a specified horizon and dependence correction. Do not apply it merely by relabeling variable-duration trade P&L as a forecast loss. | DM-HLN is a forecast-loss comparison. It does not automatically supply valid inference for selected, overlapping, variable-duration strategy trades. | Specify a separate forecast-loss estimand and horizon if forecast comparisons are in scope. |
| Power / precision / sample size | Do not set a fixed count (including 100 trades, 100 blocks, or `100 x E[L]`) now. Before a confirmatory gate, define a minimum relevant effect and desired interval precision, then simulate power/coverage under a preregistered dependence and outcome-generating model. Freeze the simulation assumptions and report sensitivity. | No effect size, eligible evidence unit, dependence model, or precision target is currently approved; an arbitrary count is not a defensible threshold. | Set the minimum relevant effect, confidence/precision target, error rates, simulation scenarios, and whether the gate is power- or precision-based. |
| Interim looks and stopping | Keep any existing negative-expectancy/drawdown pause as a safety stop only, with its equity series, boundaries, and persistence rules defined. Permit no interim efficacy claim unless a sequential method and error-spending rule are frozen in advance. | Repeated unadjusted looks inflate false-positive risk. A safety pause is not confirmatory success/failure. | Approve pause metrics, review cadence, and any sequential efficacy procedure. |
| Multiple candidates / selection | Register the complete candidate/configuration family and keep selection, tuning, preprocessing, and model calibration inside chronological training folds; preserve one untouched common test interval. Treat PBO/CSCV and Deflated Sharpe as secondary selection-bias diagnostics only when their assumptions and trial counts are met. | These diagnostics cannot repair leakage, an invalid dataset, or inconsistent holdouts; DSR inputs must reflect the full trial family and dependence limitations. | Freeze the candidate family, selection procedure, multiplicity policy, and any secondary diagnostic before test access. |
| Prospective evidence | Keep retrospective replay/development data distinct from untouched prospective observations. Do not promote historical replay results to confirmatory evidence. | Replayed historical data are not fresh prospective observations. | Define a separate prospective protocol only after source, collector, ledger, and gate governance are approved. |

## Method assessment for the proposed estimands

- **DM-HLN:** Potentially suitable for paired, aligned forecast-loss differentials at a fixed target/horizon, with the serial-correlation adjustment and `t_(T-1)` reference distribution specified by protocol. It is not a generic test for trade-level expectancy or variable-duration returns.
- **Stationary/block bootstrap:** Potentially suitable for uncertainty on an ordered, dependent calendar-time series if the resampling unit, expected block-length rule, finite-sample limitations, and sensitivity analysis are frozen. Expected block length does not multiply the observed sample count.
- **PBO / CSCV:** A secondary assessment of selection overfitting under a sufficiently specified trial/partition structure. It cannot validate point-in-time features, replace a chronological untouched test, or stand in for a confidence interval on the primary estimand.
- **Deflated Sharpe Ratio:** A secondary selection-bias diagnostic only if the trial count, return series, dependence, and distributional inputs are reported. It is not a profitability guarantee and does not substitute for a primary effect estimate and uncertainty interval.

## Approval boundary

This matrix is a review proposal, not an automated acceptance rule. No numerical sample threshold, confirmatory status, gate code, or protocol replacement is approved by this document. V1.1 and the existing V1.2 proposal are preserved. Human review must resolve the choices in the final column before any statistical gate is implemented.
