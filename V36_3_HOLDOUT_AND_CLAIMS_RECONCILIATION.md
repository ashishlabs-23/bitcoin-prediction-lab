# BTCognitive V36.3 — Holdout Custody and Claims Reconciliation

## Custody classification

**Holdout custody: `UNVERIFIABLE`**

`holdout_custody_manifest.json` says `SEALED_UNTOUCHED` for `2025-10-08T00:00:00Z` through `2026-10-07T03:11:00Z`, tied to the full 1m dataset SHA and 2,662 trades. It is a status assertion, not evidence of physical isolation, immutable holdout storage, access control, or access logs. The full source CSV is locally available. `run_full_research_pipeline.py::run` computes candidates and resolves outcomes for the full input before separating `research_trades` from `holdout_trades`; it then writes the custody manifest itself. This means the pipeline does not enforce a sealed holdout boundary at label-generation time. However, the inspected source only trains/evaluates on `research_trades`; there is no direct evidence here that holdout outcomes were used to tune a model. Therefore this audit does not claim proven use, but the untouched/sealed claim is not verifiable and the holdout cannot be treated as confirmatory.

The 500-row pilot is described by `feasibility_audit.md` as sampled across the 14.7-year dataset, while `pilot_labels_manifest.json` records 500 labels and the full dataset hash. The label sample was not opened or used here. Because a date-level exclusion/access record is absent, whether the pilot contains outcomes from the stated holdout period is **unresolved**. The old holdout must remain unavailable for confirmatory claims unless independent custody evidence resolves this.
